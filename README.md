# 工会战报刀 BOT（QQ 官方群机器人）

基于 NoneBot2 + QQ 官方适配器，面向《巨乳ファンタジーバースト》同盟战。
当前支持 QQ 群消息；不包含 QQ 频道、私聊或 OneBot 登录方式。

## 安装与官方接入

需要 Python 3.11+，以及在 QQ 开放平台创建、具有群聊能力的机器人。

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# 编辑 .env 后启动：
.venv\Scripts\python.exe bot.py
```

1. 在 `.env` 的 `QQ_BOTS` 中填写 AppID 和 AppSecret。适配器要求存在 `token` 字段；后台有 Token 时填写，无则保留空字符串。凭据只放本地 `.env`。
2. 在 QQ 开放平台为应用启用所需的群消息事件（例如 `GROUP_AT_MESSAGE_CREATE`）、收图和发图能力；按平台要求配置测试群/发布范围。`intent` 配置不能代替后台开通权限。
3. 使用 Webhook 接入：将公网 HTTPS 地址 `https://你的域名/qq/webhook` 反向代理到 `http://127.0.0.1:8080/qq/webhook`，保留原始请求体及 `X-Bot-Appid`、签名相关请求头。适配器处理回调验证和签名校验，`QQ_VERIFY_WEBHOOK` 保持开启。
4. 在群内发送 `@机器人 我的身份`，机器人返回 AppID、用户 OpenID、群 OpenID。
5. 将管理员配置项填入 `GW_ADMINS=["AppID:用户OpenID"]`，多个管理员以逗号分隔，重启后生效。未配置时无人拥有管理权限；QQ 群管理身份不自动获得机器人管理权限。

默认采用 Webhook，驱动为 `fastapi+httpx`。服务不会自动部署公网地址，也不会替你创建官方应用。
沙箱与生产环境请按应用实际支持情况配置 `QQ_IS_SANDBOX`。

参考：[QQ 开放平台](https://q.qq.com/)、[NoneBot QQ 适配器](https://github.com/nonebot/adapter-qq)。

## 指令

默认在群内 `@机器人` 后发送以下命令，支持可选 `/` 前缀。
具体可收到哪些消息、附件由官方后台权限和事件范围决定。

| 指令 | 用途 | 权限 |
|------|------|------|
| `我的身份` | 查看当前官方身份标识，供管理员配置使用 | 所有人 |
| `设置作业 [名称]` + 一张图片 | 保存/覆盖本群作业 | 管理员 |
| `作业 [名称]` | 获取作业；别名 `查看作业`、`抄作业` | 所有人 |
| `设置BOSS <第几只> <满血> [剩余血量]` | 校准当前 BOSS、保存本群血量配置并开启工会战 | 管理员 |
| `开启工会战` | 从第 1 只开始，须已配置其血量；进行中不会重复重置 | 管理员 |
| `结束工会战` | 结束当前工会战 | 管理员 |
| `报刀 <伤害>` | 记录伤害，达到剩余血量时自动作为尾刀 | 所有人 |
| `补偿刀 <伤害>` | 使用尾刀获得的补偿刀 | 所有人 |
| `撤刀` | 撤销最近个人记录（现有回滚限制见下文） | 所有人 |
| `预约` / `取消预约` | 预约当前 BOSS | 所有人 |
| `出刀进度` / `BOSS状态` | 查看记录和 BOSS 剩余血量 | 所有人 |
| `今日汇总` | 生成并上传今日统计图 | 所有人 |
| `催刀` | 回复今日已报刀成员的剩余刀数 | 管理员 |

## 作业图片

管理员将 `@机器人 设置作业 火队` 与一张配置图片放在同一条消息中发送。
成员通过 `@机器人 作业 火队` 查询；省略名称时使用默认作业。

图片最多 10 MB、2500 万像素，下载和验证成功后才覆盖旧图。
图片二进制保存在 `data/guild_war.db` 中，避免 QQ 临时下载链接过期；重启保留，各群独立。
回复时通过官方媒体接口上传，再携带触发消息的 `msg_id`、`msg_seq` 发回图片。
目前不支持引用旧消息取图或分两条消息设置；输入消息必须确实包含官方回调附件。

## BOSS 血量与校准

原先的“混沌核心”五段血量是示例，已经移除，不能作为本游戏真实数值。
本次公开检索没有找到可以核实的完整逐级血量表。

- Wiki 记载：第 40 只 BOSS 达到 Lv120，后续等级保持 Lv120。“第几只”与游戏 Lv 不是同一概念。
- 末段 **102.5 亿 = 10,250,000,000** 是用户于 2026-09-25 提供的记忆值，尚未独立核实。
- 当前暂以第 40 只及以后为末段，使用上述记忆值；“末段 HP 从第40只起重复”属于待验证配置，不是从 Wiki 得到的 HP 结论。
- 第 1～39 只暂缺血量。首次开战必须先校准当前 BOSS；推进到未知血量时记录该次击杀并进入待配置状态，禁止继续扣血/消耗补偿刀。

例如，确认游戏当前处于末段后：

```text
@机器人 设置BOSS 40 10250000000
@机器人 设置BOSS 40 10250000000 8000000000
```

第一条表示满血；第二条表示满血 102.5 亿、剩余 80 亿。
这个命令会改变当前进度，但不会删除此前报刀记录、退还刀数或清空预约。
第 40 只及以后的校准会覆盖本群末段血量。低等级按各只单独保存，其他群不受影响。
也可将已核实的通用数值补入 `config.py` 的 `BOSS_HP_BY_ROUND`，重启生效；本群校准值优先。
详细检索记录见 [血量来源说明](docs/boss-hp-research.md)。

## 催刀

手动催刀作为当前群消息的被动回复，不调用旧 OneBot 的 `send_group_msg`。
当前使用成员显示名，不假设官方接口允许任意 @成员；姓名缺失时显示 OpenID 前 8 位。
没有完整成员名单，所以只统计今日已报刀成员，不再宣称“全员出刀完毕”。

主动定时催刀默认关闭。取得官方主动消息权限/群授权并确认额度后，配置：

```dotenv
GW_ENABLE_PROACTIVE_REMINDERS=true
GW_REMINDER_TARGETS={"你的AppID":["目标群OpenID"]}
```

时间为北京时间 20:00、22:00，可修改 `config.py` 的 `REMIND_TIMES`。
不会借用过期消息 ID，也不自动重试被平台拒绝的消息。平台不允许主动消息时请使用手动催刀。

## 架构与旧数据

- `qq_gateway.py`：官方身份映射、管理员权限、被动文字/图片回复。
- `handlers.py`：官方群消息命令入口。
- `services.py`：工会战业务，接收 `GuildContext`，不依赖 QQ 事件或 Bot 对象。
- `homework.py`：作业收图、校验、持久化与查询。
- `database.py` / `models.py`：SQLite 存储和领域模型。
- `scheduler.py` / `chart.py`：催刀调度和统计图生成。

官方群键为 `qq:AppID:group:群OpenID`，用户键为 `qq:AppID:user:用户OpenID`。
旧数字 QQ 号数据保留在数据库中，但不会自动映射到 OpenID；切换后需重新设置作业与当前 BOSS。
仅凭旧 QQ 号无法可靠推导官方 OpenID。当前入口只注册官方 QQ 适配器。

## 仍需完善

本次完成官方接入边界和作业迁移，以下原有业务问题仍需单独改造：

- 撤刀尚未做到完整回滚：他人后续伤害、跨 BOSS、补偿刀以及校准后的撤刀仍可能不一致。
- 报刀和补偿刀操作尚未事务化；多人并发、回调重复投递可能重复记账或丢失伤害。
- 没有完整工会成员名册；零出刀成员不出现在进度/催刀中。
- 日期仍按服务器本地零点划分，尚未实现 Wiki 描述的凌晨 3 点刷新和完整战期管理。
- 目前只预约当前 BOSS；独立的“尾刀”命令尚未实现，请使用“报刀”。
- 需要真实官方应用验证回调、图片收发、权限/额度和上线范围；本地测试没有真实凭据。
